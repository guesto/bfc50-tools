# bfc50-tools

Русский · [English](README.md)

Экспериментальные инструменты на Python для резервного копирования, просмотра и программирования **памяти каналов Baofeng BF-C50**. Код прошивки и загрузчик не заменяются.

Поводом для работы стала незавершённая поддержка BF-C50, описанная в [тикете CHIRP #10176](https://chirpmyradio.com/issues/10176). Здесь предложен самостоятельный способ работы и зафиксированы наблюдения о протоколе; сам CHIRP этот проект не изменяет.

Протокол и разметка проверены предыдущими скриптами на **двух BF-C50**, с кабелем Prolific PL2303 под Ubuntu. Этот проект — переработка тех скриптов с тестами на имитаторе. Другие аппаратные ревизии не проверены. Проект независимый, это не официальное ПО Baofeng и не драйвер CHIRP.

Установленный пакет прошёл аппаратную проверку на одной подключённой рации: резервная копия, временная смена CTCSS канала 16, полное обратное чтение, возврат исходной конфигурации и независимая проверка. Все исходные байты восстановлены. См. [результаты](docs/VALIDATION.md).

## Базовый профиль

В `profiles/pmr446-8.csv` записаны первые восемь аналоговых частот PMR446 из согласованной сетки для использования в РФ. Все каналы — **симплекс, NFM, CTCSS OFF на передачу и приём**.

| Канал | Частота, МГц | CTCSS TX | CTCSS RX |
|---|---:|---|---|
| 1 | 446.006250 | OFF | OFF |
| 2 | 446.018750 | OFF | OFF |
| 3 | 446.031250 | OFF | OFF |
| 4 | 446.043750 | OFF | OFF |
| 5 | 446.056250 | OFF | OFF |
| 6 | 446.068750 | OFF | OFF |
| 7 | 446.081250 | OFF | OFF |
| 8 | 446.093750 | OFF | OFF |

По умолчанию незаданные позиции **9–16 очищаются**. С `plan --unused preserve` незаданные каналы сохраняются. Глобальные настройки и исходные биты мощности сохраняются. Одна смена сетки не подтверждает соответствие рации требованиям к радиооборудованию: мощность, девиация и побочные излучения не измерялись, действующие условия использования в РФ нужно проверить отдельно. Описание PMR446: [CEPT ECC/DEC/(15)05](https://docdb.cept.org/document/448).

## Установка

Нужны Python **3.10+** и программирующий USB-кабель. На аппаратуре проверен Linux; работа последовательного порта под Windows/macOS в этом проекте аппаратно не проверялась.

Из скачанного или клонированного проекта:

```bash
cd bfc50-tools
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
bfc50 --help
```

Все дальнейшие команды выполняются из корня проекта с активированным `.venv`. В новом терминале повторите `source .venv/bin/activate`. В Ubuntu вне окружения используйте `python3`; после активации доступна команда `python`. Для выхода из окружения выполните `deactivate`.

Под Windows создайте окружение командой `python -m venv .venv`; активация в PowerShell: `.venv\Scripts\Activate.ps1`, пример порта — `COM3`. Вместо команды `bfc50` можно использовать `python -m bfc50_tools`.

## Подключение и резервная копия

Выключите рацию, вставьте оба штекера до упора, включите рацию. При программировании PTT нажимать не нужно.

На двух проверенных экземплярах с подключённым кабелем не было обычных звуковых или визуальных признаков включения и выключения. Для каждого предполагаемого переключения питания удерживайте кнопку **около 2 секунд**. По отсутствию звука нельзя определить, включена ли рация: связь проверяется командой `probe`. Не нажимайте PTT и не переключайте питание во время активного чтения или записи.

```bash
bfc50 ports
# Пример для Linux: укажите порт, который найден на вашем компьютере.
sudo setfacl -m "u:$(id -un):rw" /dev/ttyUSB0
bfc50 probe --port /dev/ttyUSB0
bfc50 read --port /dev/ttyUSB0 --output backups/radio1.bin
bfc50 inspect --image backups/radio1.bin
```

Команда `setfacl` относится к Linux. После переподключения USB права могут потребоваться снова. Можно использовать постоянное имя `/dev/serial/by-id/...`. Команда `probe` проверяет рукопожатие и ID `50 33 31 30 37 f7 00 00`. Этот ID не является уникальным серийным номером или гарантией модели: используйте программу только с BF-C50, разметку которой проверили.

`read` сохраняет **1632 байта конфигурации**, соседний JSON с SHA256 и журнал обмена. Существующая копия не перезаписывается. У каждой рации должна быть собственная резервная копия.

## Подготовка, просмотр, запись и проверка

Подготовьте план без подключения к порту. По умолчанию используется базовый профиль из восьми каналов:

```bash
bfc50 plan --baseline backups/radio1.bin --output plans/radio1-pmr
```

Создаются три файла:

- `plans/radio1-pmr.json` — настройки, список изменяемых каналов и контрольные суммы.
- `plans/radio1-pmr.baseline.bin` — копия выбранного исходного состояния.
- `plans/radio1-pmr.bin` — ожидаемый образ после записи.

Храните их вместе. Просмотрите выведенные настройки и JSON. Команда `plan` не открывает последовательный порт.

```bash
# Дополнительная проверка плана без открытия порта:
bfc50 write --port /dev/ttyUSB0 --plan plans/radio1-pmr.json

# Выполнение записи:
bfc50 write --port /dev/ttyUSB0 --plan plans/radio1-pmr.json --apply

# Отдельное повторное чтение и сравнение:
bfc50 verify --port /dev/ttyUSB0 --plan plans/radio1-pmr.json
```

Перед записью текущее состояние рации должно побайтно совпасть с исходной копией в плане. Записываются только изменённые 16-байтовые ячейки каналов в области `0x0000..0x00ff`. После подтверждения каждого блока вся доступная область в 1632 байта считывается и сравнивается. При ошибке программа пытается восстановить затронутые ячейки и отдельно проверяет восстановление. Если восстановление не подтверждено, состояние нужно исследовать по журналу; ошибка не означает, что память осталась прежней.

Журналы и снимки до записи, после записи и после восстановления сохраняются в `logs/`. Параметр `--log-dir` задаёт другой каталог. Признак успеха: `VERIFIED: full memory matches the plan`. При отсутствии изменений выводится `UNCHANGED`, записи ячеек нет.

Если исходное состояние изменилось, снимите новую копию и создайте новый план. Не используйте копию другой рации. Даже переключение канала может изменить байт `0x0645`: строгая проверка всей памяти после обычного использования тогда завершится ошибкой, хотя поле `channels_match` в журнале будет истинным. Проверьте различия, прежде чем повторять запись.

После завершения отключите кабель, перезапустите рацию и проверьте связь. Для второй рации повторите процедуру с её собственного `read` и с новыми именами выходных файлов.

## Свои настройки

Создайте редактируемую копию встроенного профиля:

```bash
bfc50 init-profile --output my-channels.csv
```

Редактируйте CSV в текстовом редакторе или таблицах. Сохраните **UTF-8, разделитель запятая, десятичный разделитель точка**. Здесь используется собственный небольшой формат CSV; это не формат импорта CHIRP.

```csv
Channel,Name,Frequency,TxCTCSS,RxCTCSS,Mode,Template
1,Group,446.006250,91.5,91.5,NFM,
2,Open,446.018750,OFF,OFF,NFM,
9,Open-copy-1,446.006250,OFF,OFF,NFM,1
```

| Поле | Значение |
|---|---|
| `Channel` | Уникальный номер 1–16; можно задавать только нужные строки и менять их порядок |
| `Name` | Подпись в CSV; в безэкранную рацию не записывается |
| `Frequency` | Частота приёма и передачи в МГц, симплекс, кратность 10 Гц |
| `TxCTCSS` | `OFF`, пустое поле или стандартный CTCSS в Гц |
| `RxCTCSS` | Независимо задаваемый тон приёма или `OFF`/пустое поле |
| `Mode` | `NFM`; другие режимы в этой версии не предлагаются |
| `Template` | Пустое поле сохраняет флаги и неизвестные байты этой ячейки. Для включения пустой ячейки укажите активный канал **из исходной копии**, например `1`: из него копируются биты мощности и прочие параметры. |

Допустимый программой диапазон UHF 400–470 МГц взят из исследованного драйвера; эти границы не подтверждают RF-характеристики и разрешение на передачу. VHF 145 МГц, запись DCS, репитерный сдвиг и управление мощностью не реализованы. CTCSS фильтрует приём, но не делает связь приватной.

После редактирования создайте отдельный план:

```bash
bfc50 plan --baseline backups/radio1.bin --profile my-channels.csv \
  --unused preserve --output plans/radio1-custom
bfc50 write --port /dev/ttyUSB0 --plan plans/radio1-custom.json --apply
```

`--unused preserve` подходит для изменения отдельных каналов. Без него все отсутствующие в CSV позиции отключаются. `Template` относится к каналу исходной копии, а не к новой строке CSV. Чтобы изменить план, исправьте CSV и создайте новый план: вручную редактировать образы и хеши не нужно.

## Тестирование и разработка

Из корня проекта после установки зависимостей:

```bash
source .venv/bin/activate
python -m unittest discover -s tests -v
python -m compileall -q bfc50_tools
python -m bfc50_tools --help
```

Тестовые образы синтетические. Тесты проверяют CSV, кодирование, сохранение глобальных настроек, отдельные сеансы чтения/записи, варианты эха, неверную исходную копию, потерю подтверждения, восстановление и команды без подключения к порту. Физическая рация для них не нужна. GitHub Actions настроен на Python 3.10, 3.12 и 3.14.

При изменении протокола сначала проверьте `probe` и `read`, затем минимальное изменение канала с собственной резервной копией. В отчёте укажите маркировку модели, ID, ОС, кабель, точные команды, результат и соответствующий журнал. Уберите из публикуемого журнала посторонние локальные пути.
